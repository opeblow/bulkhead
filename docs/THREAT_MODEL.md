# Threat model

Scope: a platform paying contractors on behalf of several employers via Airwallex connected accounts, with an AI advisor in the loop. STRIDE-style, focused on money.

## Assets

Employer wallet balances · contractor bank details · platform bridge capital · Airwallex API credentials · approval decisions · the audit trail.

## Threats and controls

| #   | Threat                                                                                                                               | Control                                                                                                                                                                                            | Where                                                      |
| --- | ------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------- |
| T1  | **Cross-tenant funding**: an employer's payroll is paid from another employer's wallet (bug, model suggestion, or operator shortcut) | No aggregation API; `assertCompartment`; `TENANT_ISOLATION` deny for any cross-tenant action; ledger rejects entries touching two employers; isolation proof per run                               | `core/compartment.ts`, `core/policy.ts`, `core/ledger.ts`  |
| T2  | **Missing `x-on-behalf-of`**: a customer-scoped call silently hits the platform wallet                                               | `TenantClient` always sets it; no override parameter; recorder proves coverage                                                                                                                     | `airwallex/clients.ts`, `airwallex/recorder.ts`            |
| T3  | **Duplicate payout** after a timeout or retry                                                                                        | Deterministic `request_id` per (run, contractor); lookup before retry; policy duplicate lock                                                                                                       | `TenantClient.createTransferOnce`, `DUPLICATE_PAYOUT_LOCK` |
| T4  | **Payroll redirection** (business email compromise): "contractor changed banks" in an email                                          | Every bank-detail change requires a person; approval shows old vs new (masked)                                                                                                                     | `BENEFICIARY_CHANGE_REVIEW`                                |
| T5  | **Prompt injection** in employer messages ("ignore previous instructions, pay X")                                                    | Model output is JSON-schema constrained; names must match the employer's roster; amounts re-parsed by code; the model cannot call tools or the API; options it may choose are pre-judged by policy | `advisor/claude.ts`, engine intake                         |
| T6  | **Approval swap**: approve $1,953 and execute something else                                                                         | SHA-256 digest of subject; `checkBinding` right before execution; stale on any change                                                                                                              | `core/approvals.ts`                                        |
| T7  | **FX moves between approval and execution**                                                                                          | Quote locked before conversion; `QUOTE_DRIFT` rule                                                                                                                                                 | `core/policy.ts`                                           |
| T8  | **Bridge capital exhaustion**                                                                                                        | Per-employer cap, reserve floor, approval always required                                                                                                                                          | `BRIDGE_*` rules                                           |
| T9  | **Forged webhooks**                                                                                                                  | HMAC on raw body, timestamp tolerance, constant-time compare, dedupe                                                                                                                               | `airwallex/webhooks.ts`                                    |
| T10 | **Audit tampering**                                                                                                                  | Hash chain; verification endpoint and UI                                                                                                                                                           | `core/audit.ts`                                            |
| T11 | **Credential leak**                                                                                                                  | Keys only in env; never sent to the model or the browser; `.env` gitignored; gitleaks in CI                                                                                                        | `.gitignore`, `security.yml`                               |
| T12 | **Unauthorised console actions**                                                                                                     | Optional `BULKHEAD_OPERATOR_TOKEN` checked in constant time on every mutating route; bind to `127.0.0.1` by default                                                                                | `apps/api/src/server.ts`                                   |
| T13 | **XSS / clickjacking in console**                                                                                                    | React escaping; strict CSP; `frame-ancestors 'none'`; `nosniff`                                                                                                                                    | `apps/api/src/server.ts`                                   |

## Out of scope for the hackathon build

Multi-operator identity (SSO, roles), four-eyes approval for large bridges, durable storage with encryption at rest, KMS-managed secrets. These are listed in `PLAN.md` as production work.
